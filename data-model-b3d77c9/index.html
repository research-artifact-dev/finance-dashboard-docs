    Data Model¶

    The Finance Intelligence Dashboard uses seven Core Data Services (CDS) entities defined in db/schema.cds. Each entity maps directly to an OData V4 entity set exposed by the FinanceService, and all entities are seeded with mock data in CSV files under db/data/ for local development.

    The data model is intentionally flat to maximize OData query performance and simplify frontend binding. Relationships between entities are navigated at the service level through OData query parameters.

    Entity Definitions¶

    The CDS schema defines the following entities in the db namespace:

    Invoices¶

    The Invoices entity is the central business object. It captures the full lifecycle of a single invoice, from the raw vendor amount through tax calculation, AI validation, compliance scoring, and final disposition.

    Invoice Entity Fields

    Field Type Description
    `ID` String \(key\) Unique invoice identifier
    `vendor` String Vendor or supplier name
    `amount` Decimal\(15, 2\) Gross invoice amount
    `tax` String Tax type identifier \(for example, VAT, GST\)
    `taxAmount` Decimal\(15, 2\) Calculated tax amount
    `score` Integer AI-assigned validation score \(0–100\)
    `status` String Processing status \(for example, Pending, Approved, Rejected\)
    `date` Date Invoice date
    `complianceScore` Integer Compliance assessment score \(0–100\)
    `riskLevel` String Risk classification \(High, Medium, Low\)
    `aiVerdict` String AI agent decision summary
    `details` String Human-readable invoice summary
    `referenceNumber` String External reference or purchase order number
    `currency` String ISO 4217 currency code
    `validationErrors` String Comma-separated list of AI validation errors
    `vatRate` String Applicable VAT rate as a percentage string
    `netAmount` Decimal\(15, 2\) Net amount before tax

    Supporting Entities¶

    The following entities provide supporting reference data for the dashboard:

    Supporting Entities

    Entity Purpose Key Fields
    `ComplianceScores` Category-wise compliance metrics shown as progress bars `category`, `percentage`, `color`, `description`
    `Alerts` Risk and anomaly alerts with severity classification `title`, `severity`, `status`, `details`, `color`
    `AgentStatus` Real-time operational status of each AI agent `name`, `subtitle`, `status`, `icon`
    `PipelineStages` Definition and current status of each processing pipeline stage `title`, `subtitle`, `status`, `order`
    `KPIMetrics` Key performance indicator values with trend direction `title`, `value`, `trend`, `trendDir`
    `MonthlyTrends` Historical monthly invoice volume for bar chart visualization `month`, `value`, `year`

    Mock Data¶

    All entities are seeded with CSV files in db/data/. The file naming convention is db-EntityName.csv. These files are loaded automatically when you run the application in development mode using npm run watch.

    The mock data includes sample invoices with varied compliance scores and risk levels, so you can test all dashboard states without connecting to a real data source.

    Tip:¶

    To add your own test invoices, edit db/data/db-Invoices.csv directly and restart the development server. The SAP CAP runtime reloads CSV data on restart.

    CDS Source¶

    The complete CDS data model is in db/schema.cds. The full namespace is db, and all entities are referenced in the service layer as db.EntityName.

    namespace db;

entity Invoices {
    key ID               : String;
        vendor           : String;
        amount           : Decimal(15, 2);
        tax              : String;
        taxAmount        : Decimal(15, 2);
        score            : Integer;
        status           : String;
        date             : Date;
        complianceScore  : Integer;
        riskLevel        : String;
        aiVerdict        : String;
        details          : String;
        referenceNumber  : String;
        currency         : String;
        validationErrors : String;
        vatRate          : String;
        netAmount        : Decimal(15, 2);
}

    For guidance on OData support in SAP CAP, see Maintaining OData Services in SAP HANA Cloud .
